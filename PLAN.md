Phases are done in order. Each has tasks to tick and acceptance criteria that define "done". Phases 0 to 5 are the MVP: a usable editor that saves and exports. Everything after builds on it.

\## Phase 0: Scaffold



\- \[x] Next.js 15 project with TypeScript strict, Tailwind v4, shadcn/ui, Lucide, Zustand, pnpm

\- \[x] `docker-compose.yml` with Postgres 16 and a named volume; `.env.example` with `DATABASE\_URL`, `DATA\_DIR`

\- \[x] Prisma set up with the initial schema below and a first migration

\- \[x] Scripts from `CLAUDE.md` all exist: `typecheck`, `lint`, `test`, `e2e`, `db:migrate`, `db:seed`

\- \[x] Vitest and Playwright configured, one trivial passing test in each

\- \[x] Light and dark theme toggle



Initial schema (after this phase, `prisma/schema.prisma` is the source of truth):



\- \*\*Project\*\*: id, title, width, height, unit (`px` | `mm` | `in`), thumbnailPath, createdAt, updatedAt

\- \*\*Page\*\*: id, projectId, order, schemaVersion, canvasData (Json), updatedAt

\- \*\*Asset\*\*: id, kind (`image` | `svg` | `font`), path, mimeType, fileSize, width, height, createdAt

\- \*\*Template\*\*: id, title, category, width, height, tags (string\[]), thumbnailPath, pages (Json: array of canvasData), isBuiltIn, createdAt

\- \*\*BrandKit\*\*: id, name, colors (string\[]), logoAssetIds (string\[]), fonts (Json)



Acceptance:

\- A fresh clone reaches a running app with `docker compose up -d db`, `cp .env.example .env`, `pnpm install`, `pnpm db:migrate`, `pnpm dev`.

\- All check commands pass.



Notes:

- Versions: Next 15.5.29, React 19.1, Fabric pinned to 6.9.1 (npm "latest" is now v7, which the stack rules out), Tailwind 4.3, Prisma 7.10.1 (npm "latest" tag points at an 8.0 release candidate, so 7.x stable is pinned).

- Prisma 7: the connection URL lives in `prisma.config.ts` (loads `.env` via dotenv), not in the schema. The client is generated into `lib/generated/prisma` (gitignored, regenerated by `postinstall`) and uses the `@prisma/adapter-pg` driver adapter; server code imports it through `lib/server/db.ts`. `prisma migrate dev` no longer runs generate, so `pnpm db:migrate` runs both.

- `Project.width/height` and `Template.width/height` are Float pixels at 96 DPI (mm-based presets like A4 are not whole pixels). `unit` and asset `kind` are Postgres enums. Pages cascade-delete with their project. `Asset.path` is relative to `DATA_DIR`.

- `pnpm db:seed` exists but only checks the database is reachable; templates come in phase 7.

- shadcn/ui: `components.json` written by hand (the 4.x CLI's `init` no longer takes a base-colour flag), zinc tokens in `app/globals.css`, only `button` added so far. Theme via `next-themes` (class strategy, follows the system by default); the toggle sits in the header of the placeholder home page.

- Fonts come from the `geist` package rather than `next/font/google`, so builds do not need internet access.

- Compose project name is pinned to `opencanva`, so the volume is `opencanva_pgdata` regardless of the folder name. Postgres binds to 127.0.0.1:5432 only.

- `pnpm.onlyBuiltDependencies` allows install scripts for Prisma and esbuild; the optional native `canvas` dependency of Fabric is deliberately not built (only needed for Fabric in Node).

- Vitest test: `lib/utils.test.ts`. Playwright test: `e2e/theme.spec.ts` (toggle, persists across reload); Playwright starts `pnpm dev` itself and needs `pnpm exec playwright install chromium` once.

\## Phase 1: Editor core



\- \[x] Dashboard at `/` listing projects, with "New design" (presets: Instagram Post 1080×1080, Story 1080×1920, Presentation 1920×1080, YouTube Thumbnail 1280×720, A4, custom size)

\- \[x] Editor at `/design/\[id]`, loaded client-only: top bar, left rail, panel, canvas viewport, bottom bar

\- \[x] Fabric canvas showing the page as an artboard on a neutral workspace, centred and fitted on load

\- \[x] Zoom with Ctrl/Cmd + wheel towards the cursor, zoom control in the bottom bar, "fit to screen"

\- \[x] Pan with Space + drag and middle mouse button

\- \[x] Elements panel: rectangle, ellipse, triangle, star, line, arrow

\- \[x] Text panel: heading, subheading, body presets; double-click to edit in place

\- \[x] Select, multi-select (Shift-click and marquee), move, scale, rotate

\- \[x] Shortcuts: Delete/Backspace, Cmd/Ctrl+D duplicate, Cmd/Ctrl+C/V/X, Cmd/Ctrl+A, arrow keys nudge 1 px (10 px with Shift), Escape deselect. Shortcuts do not fire while editing text or typing in an input.



Acceptance:

\- Playwright: create a project, add a rectangle and a text, move the rectangle, duplicate it, delete one, and the object count on the canvas is as expected at each step.

\- Zooming keeps the point under the cursor in place; panning and zooming never move objects relative to the artboard.

\- Objects outside the artboard are clipped visually but remain selectable.



Notes:

- Artboard rendering: scene coordinates are page pixels with the page at (0, 0). `canvas.clipPath` clips drawing to the page (Fabric hit-testing ignores it, so objects outside stay selectable); the white page and its shadow are painted afterwards with `destination-over` in `after:render`; `controlsAboveOverlay` keeps selection handles visible outside the page. The workspace colour is CSS behind a transparent canvas.

- The page is always white for now; a page background colour belongs with the Design panel / templates later.

- Zoom and pan only ever change the viewport transform (`lib/canvas/viewport.ts`, maths in `viewport-math.ts`, unit tested). Ctrl/Cmd + wheel (and trackpad pinch) zooms to the cursor, a plain wheel scrolls the view (Shift for horizontal). Zoom range 5 % to 1000 %; the +/- buttons step through preset levels around the viewport centre. When panels open or the window resizes the view stays centred on the same point.

- Space + drag and middle-drag pan via a capturing `mousedown` on the viewport, so Fabric never starts a selection or drag.

- The mounted canvas is found through `lib/canvas/instance.ts`, so panel and bottom-bar buttons call `lib/canvas/` functions without holding Fabric objects. The canvas element is created imperatively so React StrictMode's double mount gets a fresh element.

- `lib/canvas/serialize.ts` already exists with the custom property list and the Fabric type augmentation, because clone (duplicate, copy/paste) has to carry `id`, `name`, `locked`, `role`. Phase 2 adds saving, loading and `schemaVersion` handling to it. New projects store `{ objects: [] }` with `schemaVersion` 1; nothing is saved from the editor yet, so a reload shows an empty page.

- Copy/paste uses an in-memory clipboard; repeated pastes step 20 px further each time. Cmd/Ctrl+C/V/X keep their browser default so phase 3 can listen for real paste events (images).

- Text uses Arial until the font list arrives (phase 4), so there is nothing to load before drawing. Default element sizes are tuned for a 1080 px page and scaled to the artboard.

- Elements are added at the page centre by click; dragging from the panel onto the canvas is not built (not in the plan).

- The editor sets `min-width: 1024px`; below that the window scrolls horizontally.

- E2E tests run against their own dev server (port 3100, build dir `.next-e2e`) and their own database (`<db>_test`, created, migrated and emptied by `e2e/prepare-db.ts` when that server starts), so they do not fill the development database or clash with a running `pnpm dev`. Outside production builds the editor exposes a read-only `window.__opencanva` hook that the tests use to count objects and convert coordinates.

- Verified: unit tests for units, viewport maths, shape maths and shortcut mapping; Playwright for the acceptance flow (create project, add rectangle and heading, move, duplicate, delete with counts at each step), select all / marquee / Shift-click / copy / cut / paste / nudge, shortcuts ignored while editing text, zoom to cursor and both pan methods leaving objects untouched, and clipping with selection outside the page (pixel check plus click). Screenshots checked by eye in light and dark mode.

\## Phase 2: Persistence and history



\- \[x] `lib/canvas/serialize.ts` with the custom property list and `schemaVersion`

\- \[x] Route handlers to load and save a page and to update project metadata

\- \[x] Autosave as described in `CLAUDE.md`, with the status indicator in the top bar

\- \[x] Project thumbnail generated client-side from the first page on save

\- \[x] Undo/redo per page, cap 50, Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z, buttons in the top bar

\- \[x] Inline editable project title; rename, duplicate and delete on the dashboard (delete asks for confirmation)



Acceptance:

\- Playwright: edit a design, reload the browser, and the canvas is identical (same object count, positions and custom properties).

\- Unit tests for the history stack: cap, redo cleared after a new change, restoring does not push.

\- One drag produces one undo step. Undo after a reload is empty and does not error.

\- With the network blocked, the indicator shows the failure and retry succeeds once the network is back.



Notes:

- Page format: `{ schemaVersion, canvasData: { objects } }`. `SCHEMA_VERSION` and the request validation live in `lib/page-data.ts` (no Fabric, so route handlers can use it); `lib/canvas/serialize.ts` does the Fabric side. Loading replaces only the canvas objects (`util.enlivenObjects`) instead of `canvas.loadFromJSON`, so the canvas' clip path and viewport are never touched. A page with another `schemaVersion` is refused; the first format change adds a migration there.

- Fabric writes coordinates with limited precision (3 decimals), so a value can change in the last digits once on the first save. Reloads are byte-identical after that (tested).

- Routes: `GET`/`PUT /api/pages/[id]` (a save also bumps the project's `updatedAt`), `PATCH`/`DELETE /api/projects/[id]`, `POST /api/projects/[id]/duplicate`, `GET`/`PUT /api/projects/[id]/thumbnail`. Files go through `lib/server/storage.ts` (paths relative to `DATA_DIR`, atomic writes, refuses paths outside it). The thumbnail route is the only file-serving route so far; phase 3 adds the general one.

- History (`lib/canvas/history.ts`, unit tested): snapshots are the page JSON as strings; the stack holds 50 including the current state. Changes become a step after 300 ms of quiet; a mouse press first closes any open step and no step is taken while the button is down, so add-then-drag is two steps and one drag is one. Undo and redo run one at a time and drop the selection.

- Autosave (`lib/canvas/autosave.ts`, unit tested): 2 s after the last step, one save at a time, the newest snapshot wins, a failure keeps the snapshot for Retry or the next change. Home waits for pending saves and the title rename (and asks before leaving if the save failed); the editor also saves when the tab is hidden. On tab close it sends a `keepalive` request (browser limit 64 KiB per request) and asks the browser to confirm leaving. The save on close is tested; the confirm prompt itself did not appear in headless Chromium, so that part is untested.

- Thumbnail: rendered after each successful save of the first page on a separate off-screen `StaticCanvas` (`lib/canvas/render.ts`), at most 480 px on the long side, uploaded as PNG; one at a time, newest wins, a failure only costs the thumbnail. Phase 5 export can build on the same renderer. The dashboard requests it with `?v=<updatedAt>` and the route caches versioned URLs for good.

- Title: edited in place in the top bar (Enter or blur saves, Escape cancels, empty keeps the old title), optimistic with revert on failure. Dashboard: rename (dialog), duplicate (copies pages and thumbnail, title "… (copy)"), delete (confirmation dialog; removes the thumbnail file).

- Store additions: `loadState`, `saveStatus`, `canUndo`, `canRedo`. Panels are disabled until the page has loaded, so nothing added early is wiped by the load.

- E2E: a global setup requests every route once, because the dev server compiles a route on first use and that delay made timing-sensitive tests flaky; e2e runs with 3 workers and its own `DATA_DIR` (`./data-e2e`). New tests: reload is identical, one drag is one undo step plus undo/redo/redo-cleared, undo after reload is empty without errors, failed save then Retry, save on Home and on tab close, thumbnail shown on the dashboard, title edits, dashboard rename/duplicate/delete.

\## Phase 3: Uploads, images, layers



\- \[x] Upload route handler storing files under `DATA\_DIR`, with type and size checks (PNG, JPEG, WebP, SVG; 25 MB)

\- \[x] Route handler serving stored files with cache headers

\- \[x] Uploads panel: drag and drop or file picker, grid of uploads, click or drag to place on canvas, delete

\- \[x] Paste an image from the clipboard and drop a file straight onto the canvas (both upload first, then place by URL)

\- \[x] Layers panel: list in stacking order, drag to reorder, rename, hide, lock, click to select

\- \[x] Grouping: Cmd/Ctrl+G and Cmd/Ctrl+Shift+G



Acceptance:

\- No page JSON in the database contains a `data:` URL after uploading, pasting and dropping images (assert in a test).

\- A 20 MB upload succeeds.

\- Reordering in the layers panel changes the stacking on canvas and survives reload. Locked objects cannot be moved or selected on canvas but can be selected from the panel.



Notes:

- Upload: `POST /api/assets` (multipart, field `file`). The type is decided from the file content with `image-size` (MIT), not from the name or declared type; PNG, JPEG, WebP and SVG only, 25 MB (checked in the browser, from Content-Length, and on the file). Width and height are stored, with EXIF rotation applied. SVGs without width/height get them from the viewBox, because browsers cannot draw such an SVG on a canvas. Files go to `DATA_DIR/assets/<uuid>.<ext>`.

- Serving: `GET /api/assets/[id]` with `Cache-Control: public, max-age=31536000, immutable` (a file never changes under its id) and `nosniff`; SVGs also get a sandboxing Content-Security-Policy so opening one directly cannot run script. `GET /api/assets` lists uploads.

- Deleting an upload that pages (or templates) still use answers 409 with the count; the panel then asks a second time ("Delete anyway"). Pages with a missing image still load: any object that fails to load becomes a dashed "Missing image" placeholder that saves back as the original JSON, so nothing is lost. A browser that has the image cached keeps showing it until its cache drops it.

- Images store a relative `src` (`/api/assets/<id>`) via Fabric's `srcFromAttribute`; tested that no saved page contains `data:` or an absolute URL after upload, paste, file drop and drag from the panel.

- Placement: natural size, scaled down to fit 60 % of the page; at the drop point when dropped. Cmd/Ctrl+V pastes an image from the system clipboard when there is one, otherwise the copied objects (the object paste waits one tick to see whether the browser's paste event brings an image).

- The uploads panel shows the original files as tiles (lazy-loaded). With many large uploads this downloads a lot; server-side thumbnails would need an image library and are deferred until it matters.

- Layers panel: read-only snapshot in the store (`layers`, `selectedIds`), refreshed from Fabric events once per frame; all actions call `lib/canvas/layers.ts`. Groups show as one row (no nesting yet). Locking sets `selectable`/`evented` off and all lock flags on, and hides controls (`hasControls` added to the serialized properties). Locked objects can be selected only from the panel, only alone, and are skipped by marquee, select all, nudge and Delete. Hidden objects cannot be hit on the canvas.

- Grouping: Cmd/Ctrl+G and Cmd/Ctrl+Shift+G; the group takes the stacking position of its topmost member, ungrouping puts the members back in place (tested to 0.1 px).

- History change: discrete edits (add, delete, duplicate, paste, group, ungroup, every layer action) are now an undo step of their own via `recordStep` in `document.ts`. Before, two edits within 300 ms merged into one step, so a quick add-then-delete could not be undone separately. Typing and held arrow keys still merge.

- Tests: unit tests for content sniffing, SVG sizing, asset URLs, image fit and layer drop index; Playwright for picker upload, clipboard paste, file drop, drag from the panel, stored pages free of `data:`, a 20.9 MB upload (real 2700 × 2700 noise PNG), wrong type and oversized files, SVG policy, delete-in-use with placeholder, layer reorder/rename/undo surviving reload, hide and lock behaviour, group/ungroup positions, reload and undo.

\## Phase 4: Contextual toolbar, alignment, snapping



\- \[x] Toolbar above the canvas that changes with the selection type

\- \[x] Shape: fill, stroke colour, stroke width, dash style, corner radius

\- \[x] Text: font family (a short built-in list for now), size, colour, bold, italic, underline, alignment, letter spacing, line height

\- \[x] Image: opacity, corner radius, flip, crop

\- \[x] Any selection: opacity, bring forward / send backward / to front / to back, lock, duplicate, delete

\- \[x] Colour picker: hex input, swatches of colours already used in the document, linear gradient for fills

\- \[x] Align to page and to selection (left, centre, right, top, middle, bottom); distribute horizontally and vertically for three or more objects

\- \[x] Snapping while moving: to artboard edges and centre, and to edges and centres of other objects, with visible guide lines. Hold Alt (Option) to disable.



Acceptance:

\- Unit tests for the snapping maths and for align/distribute.

\- Every toolbar control reflects the current selection's value and updates when the selection changes; with a mixed multi-selection the control shows an indeterminate state.

\- Each toolbar change is one undo step.

\- Dragging 200 objects' worth of document stays smooth by eye on the owner's machine (generate a test document for this).



Notes:

- Toolbar (`components/toolbar/`) renders only from the store's read-only `selection` snapshot (`lib/canvas/selection.ts`, refreshed on selection events and `object:modified`); every change goes through `changeSelection` in `lib/canvas/props.ts`. Each property is the shared value or `MIXED`; controls show mixed as an empty field with "Mixed", `aria-pressed="mixed"`, or a rainbow swatch. Kinds: shape, line (Line and open paths such as the arrow), text, image; groups and mixed kinds get only the common controls. A locked selection shows only Unlock.

- One undo step per toolbar change: a discrete change (button, typed value, swatch) uses `recordStep`; a slider or colour-picker drag is a live gesture that shows changes immediately and is recorded once on release (or when its popover closes). Tested for a colour change on two objects and an opacity slider drag.

- Undo and redo shortcuts now also work while focus is inside a toolbar popover (it stays on a slider after dragging); other shortcuts are still off inside dialogs and popovers. Escape closes one layer at a time, so with a tooltip showing over the trigger it takes two presses to close a popover; that is Radix's behaviour and left as is.

- Fonts: Inter, Roboto, Open Sans, Montserrat, Playfair Display, Merriweather, Oswald, Roboto Mono bundled from @fontsource (regular, bold, italics; Oswald has no italic), plus Arial from the system. Inter is now the default for new text. Faces are loaded (with the actual text, so latin-ext subsets for Czech load too) before page JSON is turned into objects, before a font change is applied, before new text is added, and when typed characters need a subset not yet loaded. Bold maps to weight 700; older text with weight 600 counts as bold.

- Text scaled by a corner handle has the scale folded into its font size and width when the drag ends, so the size field shows the real size. Not done inside multi-selections.

- Shapes: fill (solid, linear gradient with angle, or none), stroke colour, width, dash (solid, dashed, dotted). Strokes are now uniform (stay the same width however the shape is scaled). Corner radius for rectangles and images; on images it is a rounded clip path that follows crops.

- Colour picker: react-colorful (MIT) picker, hex input, the page's colours (most used first), and a few basic colours. Gradients are stored in percentage units, so they follow the object's size.

- Crop: Crop button (single image) enters crop mode; handles change the visible part instead of scaling (rotation handle hidden, corner handles free), the hidden part shows faintly, and Done, Enter, Escape or a selection change ends it. One drag is one undo step. The math is unit tested (`crop-math.ts`).

- Align to page (always), to selection (2+), distribute horizontally and vertically (3+, equal gaps, outermost stay); arrange forward/backward/front/back. All by bounding boxes in page space, unit tested.

- Snapping while dragging: page edges and centre, other objects' edges and centres, within 6 screen px whatever the zoom; pink guides; Alt disables. Targets are collected once per drag, so the cost per mouse move is a few hundred comparisons.

- Performance: `pnpm stress-doc [url]` adds a 200-object design (shapes, outlines, gradients, text) to a running app for judging by eye. The e2e test on the same document measured about 38–47 fps dragging one object and 29–38 fps dragging all 200, on the dev server, headless, with other tests running in parallel; the test only guards against a stall (> 15 fps).

- Checked by screenshots in light mode only; dark mode uses the same shadcn tokens but was not looked at for the toolbar.

\## Phase 5: Pages and export



\- \[x] Page strip at the bottom: add, duplicate, delete, reorder by drag, thumbnails

\- \[x] Switching pages saves the current page and loads the other; history is per page

\- \[x] Export dialog: format (PNG, JPEG, PDF, SVG), page selection, PNG transparent background, JPEG quality, scale (1×, 2×, 3×) for raster, DPI (96, 150, 300) for PDF

\- \[x] Multi-page raster export downloads a zip; PDF contains all selected pages

\- \[x] Fonts are awaited before every export



Acceptance:

\- A 1080×1080 page exported at 2× is exactly 2160×2160 px. An A4 project exported to PDF at 300 DPI has an A4 page size and an embedded image of about 2480×3508 px.

\- Transparent PNG has an alpha channel where the page has no background.

\- Exporting a 20-page document to PDF at 300 DPI completes without the tab crashing.

\- Exported output matches the canvas (no missing fonts, no clipped objects, hidden layers excluded).



\*\*MVP ends here.\*\* Before going on, do a pass over phases 0 to 5 for rough edges and list anything found in Notes.




Notes:

- Pages: the editor loads every page of the design once (`GET /api/projects/[id]/pages`) and keeps their latest data and undo stacks in memory (`lib/canvas/document.ts`) for as long as it is open, so going back to a page restores its history. Switching loads the other page into the same Fabric canvas (the view stays put): it ends crop and text editing, saves the page being left and waits for the save. If that save fails it asks first; the changes are then kept and saved again when the page is next opened (and closing the tab asks to confirm).
- Routes: `POST /api/projects/[id]/pages` (insert at an index, empty or with given data; at most 200 pages), `PUT /api/projects/[id]/pages` (new order, must list every page once), `DELETE /api/pages/[id]` (409 for the last page). Orders stay 0..n-1 by renumbering in a transaction.
- Page strip (`components/editor/page-strip.tsx`, logic in `lib/canvas/pages.ts`): previews rendered client-side (one at a time, re-rendered after each undo step of that page), click to open, drag to reorder, hover buttons to duplicate and delete, "+" adds a page after the open one and opens it. Page actions run one at a time. Duplicating gives every object (also inside groups) a new id. Deleting a page with content asks first; there is no undo for adding, deleting or reordering pages. The project thumbnail follows the first page, also after a reorder or delete. Copy/paste works across pages (the clipboard is in memory).
- Shortcuts and image paste are ignored while a page is loading, since the load would replace the edit.
- Export dialog (top bar): PNG (1×/2×/3×, transparent background), JPEG (1×/2×/3×, quality 10–100), PDF (96/150/300 DPI), SVG; all pages, the current page, or a typed selection ("1-3, 5"). The dialog remembers its choices while the editor is open, shows the resulting pixel size, and refuses sizes browsers cannot draw (side over 16 384 px or area over 120 MP, e.g. an 8000 px design at 3×). Cancel stops between pages.
- Rendering (`lib/canvas/render.ts`, `lib/canvas/export.ts`): each page on its own off-screen canvas, disposed and shrunk to 0 × 0 before the next, so memory holds only the compressed results. Fonts for all exported pages are loaded and `document.fonts.ready` awaited first. Hidden objects are left out before loading; stand-ins for missing images are left out of exports (they show in previews), so a page with a deleted image exports without it and without warning.
- Several PNG/JPEG/SVG files download as a zip (fflate, MIT; stored without compression except SVG), named `<title>-<page number>.<ext>`. PDF via pdf-lib (MIT): one page per design page at the physical size (px × 72 / 96 pt), each a JPEG at quality 0.92 (PNG pages at 300 DPI were several times larger). Measured in the e2e test: 20 A4 pages of 200 objects each at 300 DPI, about 6 s and 4.7 MB, no crash.
- SVG is Fabric's vector output on a white page, made self-contained: uploaded images are inlined as data URLs and the bundled font files the text needs (only the faces and unicode subsets used) are inlined as `@font-face`. Arial is not bundled and is left to the viewer. Checked by rendering an exported SVG in a blank page without the app's fonts: identical to the PNG.
- Verified: unit tests for page range parsing, reordering, fresh ids, export sizes (1080 at 2× = 2160, A4 at 300 DPI = 2480 × 3508, A4 = 595.28 × 841.89 pt), canvas limits, file names, unicode ranges and SVG embedding. Playwright: add/duplicate/delete/reorder with reload, save on switch, per-page undo and redo, cross-page paste, server rules; PNG 2× size, transparent PNG alpha (corner clear, object opaque), JPEG, A4 PDF page size and image size, zip contents for all and selected pages, hidden layer left out of PNG and SVG, SVG without `/api/assets` and with embedded image and Inter, 20-page 300 DPI PDF. Exports with several fonts, Czech text, a gradient and objects over the page edge compared by eye with the canvas; page strip and dialog looked at in light and dark mode (the current-page ring got an offset because it was invisible in dark mode).

Rough edges found in the pass over phases 0 to 5 (not fixed, for the owner to prioritise):

- The page is always white. Transparent PNG relies on that; a page background colour (and transparent-by-design pages) belongs with the Design panel / templates.
- Adding, deleting and reordering pages cannot be undone. Deleting a page with content asks first.
- A page whose image file was deleted exports without that image and without telling the person.
- The uploads panel and the page strip render from full-size originals; with many large uploads this is slow and memory-hungry (server-side thumbnails were deferred in phase 3).
- SVG export of cropped or rounded images and of text with letter spacing was not compared by eye; it relies on Fabric's SVG output.
- The page strip has no keyboard reordering (drag only) and no page names.
- Leaving the editor through Home waits for the open page's save only; a page left earlier with a failed save is lost if its retry on reopen never happens (the tab-close prompt covers closing, not Home).
- Phase 4 toolbar was only checked in light mode; the export dialog and page strip have now been checked in dark mode, the toolbar still has not.

\## Phase 6: Fonts and text effects



\- \[x] Curated list of about 60 Google Fonts families with categories, in a JSON file; loaded on demand; font picker with search and preview in each family's own face

\- \[x] Custom font upload (TTF, OTF, WOFF2) stored as an Asset and registered with the FontFace API

\- \[x] Pages load the fonts they use before rendering

\- \[x] Effects: drop shadow, outline, hollow (outline with no fill), neon (coloured glow); each with its parameters and a way to turn it off

\- \[x] Lists (bulleted, numbered) and text case toggle



Acceptance:

\- A page using five different fonts renders correctly on first load after a cold cache, and in export.

\- Effects survive save, reload, undo and export.



Notes:
- Fonts: 60 Google Fonts families in five categories (sans serif 20, serif 13, display 13, script 10, monospace 4), all with the latin-ext subset so Czech works. Each is an @fontsource package (OFL); the editor imports the regular and bold faces and their italics where the family has them (167 stylesheets). The browser downloads a face, and only the unicode subsets the text uses, when text first uses it, so nothing is fetched up front except what the font picker shows. `scripts/generate-fonts.ts` (`pnpm fonts:generate`) holds the curated list and writes `lib/font-catalog.json` and `components/editor/font-faces.ts` from the packages' metadata; a unit test checks the two agree. Permanent Marker and Satisfy were swapped for Courgette and Allura because they have no latin-ext.
- Families with only a regular face (Lobster, Bebas Neue, Pacifico and other display and script fonts) get a browser-synthesized bold or italic when those are switched on, on the canvas and in SVG export alike. Arial is no longer in the list; older text set in Arial still shows and keeps its name in the picker.
- Font picker: a popover with search (Enter picks the first match), category chips, each name drawn in its own face, and uploaded fonts in their own group at the top.
- Uploaded fonts: TTF, OTF or WOFF2, at most 10 MB, `POST /api/fonts`. The type is decided from the content; family, bold and italic are read from the font's own `name` and `OS/2` tables (WOFF2 is unpacked with Node's Brotli), using the style-linking a word processor uses, so a "Light" cut becomes its own family with a regular face. One file is one face; uploading Bold and Italic files of the same family fills in those faces. A family that is in the built-in list, or a face already uploaded, is refused (409). Faces are stored as `Asset` rows of kind `font` (new columns `fontFamily`, `fontWeight`, `fontStyle`, `fileName`; migration `font_assets`), registered with the FontFace API before the first page loads, and inlined in SVG export like the bundled ones. Deleting removes every face of a family (`DELETE /api/fonts?family=`); if pages use it, it asks first, and their text then falls back to another font. Uploaded fonts are not listed in the Uploads panel.
- Effects: one per text, picked in an Effects popover from the text toolbar: shadow (offset, direction, blur, transparency, colour), outline (thickness, colour), hollow (thickness), neon (intensity). Parameters are relative and turned into Fabric's shadow and stroke from the font size (`lib/text-effects.ts`, unit tested), so an effect keeps its look when the text is resized. The effect is stored as an `effect` property next to the Fabric values it produced. Hollow and neon draw the text colour themselves (hollow empties the fill, neon uses a pale tint plus a glow) and keep the colour in the effect, so the colour control still edits it and turning the effect off restores it; a gradient text colour becomes its first colour when one of these two is chosen.
- Lists: one toolbar button cycles bulleted, numbered, none. The markers are not characters of the text: `DesignTextbox` (`lib/canvas/text-box.ts`), registered under Fabric's own "Textbox" type so existing pages load into it, draws them in the text's font and colour with a hanging indent and wraps lines in the width that is left, and adds them to SVG export. Every paragraph is numbered, empty ones included.
- Text case: an Uppercase toggle. It is a display setting: the stored and edited text keeps what was typed (characters whose capital is longer, such as "ß", stay as they are so cursor positions still match).
- The new text properties (`effect`, `listStyle`, `textCase`) are optional additions to the page JSON, so `schemaVersion` stays 1.
- Verified: unit tests for the font catalog and search, font inspection on real WOFF2 and TrueType files, effect maths and upper-casing. Playwright: a page with five fonts (Lobster, Playfair Display, Bebas Neue, Caveat, JetBrains Mono) opened in a fresh browser context measures each text within 2 % of the browser's own measurement of that face, and its SVG embeds all five; shadow, outline, hollow and neon survive save, reload and undo (hollow restores the colour), and SVG export carries the shadow filter and outline paint order; lists and upper case survive reload with the text unchanged and the SVG has the markers; an uploaded Geist (TTF regular plus WOFF2 bold) can be picked, survives reload, embeds in SVG, refuses a duplicate, and asks before being deleted while in use; the picker filters and searches, and refuses a built-in family and a non-font file. Exported PNGs of the five fonts with Czech text, effects and a numbered upper-case list, a list being edited (wrapped line, selection) and the font picker and effects popover in light and dark mode were looked at.

\## Phase 9: Resize



\- \[x] Resize dialog with the presets from phase 1 and custom size, with "resize this design" and "copy and resize"

\- \[x] Rule: scale all objects uniformly by `min(newW / oldW, newH / oldH)`, centre the scaled content on the new artboard, and stretch full-bleed background objects (those covering the whole old artboard) to cover the new one. Nothing is scaled non-uniformly except those backgrounds, and background images use cover-crop instead of stretching.

\- \[x] Applies to all pages



Acceptance:

\- Unit tests for the resize maths, including square to portrait and landscape to square.

\- Resize is undoable; "copy and resize" leaves the original untouched.



Notes:
- Resize dialog: a "Resize" button in the top bar, next to Export. The phase 1 presets and a custom width, height and unit (px, mm, in; switching the unit converts the numbers, a preset or the current size is kept exact in pixels so A4 does not drift). "Resize this design" is off while nothing changes; changing only the unit counts as a change. "Copy and resize" makes a new design named "<title> (<size>)" with every page resized and its own thumbnail, and opens it; the original is saved and not touched.
- Rule (`lib/resize.ts`, unit tested): content scale f = min(newW / oldW, newH / oldH); every object's position and scale are multiplied by f and the scaled old page is centred on the new one. "Centre the scaled content" is read as centring the old page, not the bounding box of the objects, so a logo in a corner stays near that corner instead of moving to the middle. Full-bleed backgrounds are objects with `role: "background"` (templates) or unrotated objects whose box covers the whole old page (with 0.5 px or 0.2 % of slack); they are stretched so the old page's edges land on the new page's edges (`fitObjectsToArtboard` for templates now uses the same code). A background image is not stretched: it gets a crop of the aspect of the new page at one scale, keeping everything that was visible and showing more of the photo around it where the photo has room, otherwise the largest region it allows, centred on the old view. The natural size is read by loading the image; if that fails, only the part up to the old crop's far edge is used. Rounded corners follow the new crop.
- Only backgrounds change shape. Frames, borders and stripes that do not cover the page are scaled like everything else, so for example the Quote template's inset frame stays square in the middle of a story page. Smarter re-layout is not part of this rule.
- Applies to all pages: the editor resizes the latest data of every page (unsaved edits included) and sends the size, unit and all pages in one request (`PUT /api/projects/[id]/size`, one transaction, must list every page once). The open canvas changes size in place (clip, white page, fit to screen), so nothing reloads. `POST /api/projects/[id]/duplicate` takes the same body for "copy and resize"; without a body it is the plain copy it was.
- Undo: a resize is one step for the whole design, with Cmd/Ctrl+Z and the toolbar buttons. Page histories hold snapshots of one size, so a resize starts every page's history afresh and keeps the old histories, which come back when the resize is undone (undo can then go on into edits made before it). Undo takes back page edits first; the resize itself can be undone once every page is as the resize left it (edits on other pages have to be undone on those pages first) and while no page was added or deleted since. Redo works the same way the other way round; a new edit drops it. Undo and redo of a resize are saved like the resize. Steps done before a resize that were undone cannot be redone after it, as with any new action.
- Not done: resize is not offered from the dashboard (only in the editor). There is no "which pages" choice; all pages always change together, since a design has one size.
- Verified: unit tests for the maths (square to portrait, landscape to square, uniform scale and preserved spacing, full-bleed detection with origins, slack and rotation, background image cover crop with and without the natural size, rounded corners, coverCrop staying inside the image, history `clearRedo`). Playwright: a two-page design with a background rectangle, a box and a background photo resized to Instagram Story through the dialog (background stretched, box at the same scale moved to the vertical centre, photo covering 1080 × 1920 at one scale, both pages on the server); an edit after it is undone first, the next undo restores size and both pages, redo resizes again, and the result survives reload; copy and resize to a custom 1920 × 1080 opens a two-page copy with the right size, title and positions while the original's stored pages are unchanged and it still opens at 1080 × 1080; the size route refuses a wrong page list and an oversize side. Four templates resized across shapes (Quote to story, Title slide to square, Event night to presentation, Concert poster to YouTube thumbnail: a narrow column in the middle, as the rule says) and the dialog in light and dark mode were looked at.
- Full e2e suite (now 56 tests), two runs: 2 and 3 failures, different tests each time (templates save-as-template timeout, uploaded font, toolbar italic, brand kit), all passing when run alone. The brand kit test also fails 1 run in 4 on the phase 8 commit without these changes, so it predates this phase. The flakiness noted in phase 8 is getting worse; worth a separate look (worker count, timeouts, the brand test's shared kits, and an `EPERM` rename of template thumbnails on Windows seen in the server log).
